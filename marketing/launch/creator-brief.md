# Creator pilot brief

## One message

> Start in Claude. Finish in Codex. Keep the project.

Lians carries a bounded set of current project context into a fresh task across
supported AI coding tools, with correction, deletion, and receipt controls.

## Required demonstration

1. Use a real supported coding tool in a disposable or synthetic project.
2. Save one harmless project decision.
3. Open a visibly fresh session or different supported tool.
4. Ask a question that requires the decision.
5. Show the successful current answer.
6. Correct the decision and show that the stale value is no longer current.
7. Send viewers to `github.com/Lians-ai/Lians`.

The proof must appear in the first five seconds. Show one before/after problem;
do not stack several features into the same short. The creator should explain
the architecture only after viewers see the result.

Use the approved black, white, and lotus-blue visual system in
`marketing/video/lians-simple-video-brief.md`. Every draft must be reviewed before
publication.

## Claims creators may use

- local mode requires no Lians account or provider API key;
- Lians can carry current project context across supported sessions and tools;
- users can inspect, correct, export, and delete saved memory; and
- the documented starter path takes about two minutes for a prepared developer.

## Claims creators must not use

- “perfect memory,” “never hallucinates,” or “works with every AI”;
- guaranteed token, cost, or subscription-quota savings;
- production-ready claims for technical-preview or release-candidate features;
- confidential project content in a demonstration; or
- undisclosed sponsorship or compensation.

## Pilot scorecard

Run five creators before scaling. Continue a creator only when the audience is
relevant, the comment section shows real workflow interest, qualified visitors
activate, and the cost per activated user fits expected gross profit. Views
without activation are not success.
